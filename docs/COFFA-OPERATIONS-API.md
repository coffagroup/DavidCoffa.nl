# Coffa OS operations API contract

All routes are under `/api`, authenticated, camelCase JSON. Lists use `{ items, total, page, pageSize }`; query `q`, `page` (default 1), `pageSize` (default 25, max100), `organizationId`. DELETE archives. UUID identifiers, dates `yyyy-MM-dd`, UTC timestamps ISO8601. Customer DTOs omit internal notes, budgets, time rates and unshared records. API errors use the shared foundation format.

- Organizations: `GET/POST /organizations`, `GET/PUT/DELETE /organizations/{id}`. Fields `name,email,phone,website,address,chamberOfCommerce,vatNumber,type,status,tags,internalNotes`; filter `status,type,archived`. `GET /organizations/{id}/dossier` for authorized related counts and CRM contacts/notes. Customers see only safe own organization.
- Contacts: `GET/POST /contacts`, `PUT/DELETE /contacts/{id}`. Fields `organizationId,name,email,phone,jobTitle,isPrimary`.
- Notes (staff CRM only): `GET/POST /notes`, `PUT/DELETE /notes/{id}`. Fields `organizationId,title,body`.
- Leads (CRM staff): `GET/POST /leads`, `GET/PUT/DELETE /leads/{id}`, `POST /leads/{id}/convert`. Fields `companyName,contactName,email,phone,website,address,stage,expectedValue,expectedCloseDate,notes,tags`; stages `new,contacted,meeting,prepare_quote,quote_sent,negotiation,won,lost`. `GET/POST /leads/{id}/activities`, activity `{kind,body,dueDate,isCompleted}`. Convert atomically creates organization/contact and preserves lead context; retry returns same organization.
- Projects: `GET/POST /projects`, `GET/PUT/DELETE /projects/{id}`. Fields `organizationId,name,description,status,priority,startDate,deadline,budget,estimatedHours,sharedWithCustomer,repositoryUrl,deploymentUrl`. Status `draft,planned,development,waiting_customer,testing,completed,archived`; priority `low,normal,high,urgent`. Project detail includes safe tasks; customers read shared own projects only. Staff budget visibility requires finance permission.
- Tasks: `GET/POST /tasks`, `GET/PUT/DELETE /tasks/{id}`. Fields `organizationId,projectId,parentTaskId,title,description,assignedToUserId,status,priority,dueDate,sharedWithCustomer`; statuses `todo,in_progress,review,done`. Filter `projectId,status`. Customer read-only, own+shared task and shared project required.
- Time: `GET/POST /time-entries`, `PUT/DELETE /time-entries/{id}`. Fields `organizationId,projectId,ticketId,description,workDate,durationMinutes,isBillable,hourlyRate`. Staff time.read/write permission, financial rate/value fields require finance; billed entries immutable. `GET /time-entries/timer`, `POST /time-entries/timer/start` `{organizationId,projectId,ticketId,description,isBillable,hourlyRate}`, `POST /time-entries/timer/stop` returns persisted entry. One timer per user, historical rate preserved. Query `from,to,projectId,unbilled`.
- Tickets: `GET/POST /tickets`, `GET/PUT /tickets/{id}`. Fields `organizationId,projectId,title,description,category,priority,status,assignedToUserId`. Customers can create own tickets; status/assignee staff controlled. Status `new,in_progress,waiting_customer,resolved,closed`. `GET/POST /tickets/{id}/comments` with `{body,isInternal}`; customers cannot create/view internal comments. Detail contains authorized comments and documents. Customer replies reopen `waiting_customer/resolved` as `in_progress`. Staff replies set `waiting_customer` unless closed. Ticket notifications persist for recipient organization users.
- Documents: `GET /documents`, `GET /documents/{id}`, `POST /documents` multipart fields `file,organizationId,projectId,quoteId,invoiceId,ticketId,category,sharedWithCustomer`; `PUT /documents/{id}` `{category,sharedWithCustomer}`, `DELETE /documents/{id}`, `GET /documents/{id}/download`. Limit20MiB, PDF/images/text/Office allowlist+signature. Shared customer documents still require own organization and shared linked project; ticket attachment requires own ticket. Private S3 production / development-only private files. No public file URL.
- Notifications: `GET /notifications`, `POST /notifications/{id}/read` (own user only).
- Activities: `GET /activities` is foundation-owned.
- Dashboard: `GET /dashboard` returns role-scoped active work and activity from the current month; tasks include overdue/due-this-month items and work in progress. For staff with `finance.read`, the only financial figures are current-month invoiced revenue and recorded business expenses, both excluding VAT.
- Finance: `GET /finance?from=yyyy-MM-dd&to=yyyy-MM-dd` returns the financial report for the selected period and requires `finance.read`.
- Expenses: `GET/POST /expenses`, `GET/PUT/DELETE /expenses/{id}` requires `finance.read` or `finance.write`. Fields `date,supplier,description,netAmount,taxRate`; tax and total are calculated from the net amount. DELETE archives the record.

No public anonymous registration or access to CRM lists. Customer writes ignore/reject foreign organization IDs. Staff permissions use exact `.read`/`.write` suffixes: `crm.read/write`, `projects.read/write`, `time.read/write`, `tickets.read/write`, `documents.read/write`; financial fields additionally require `finance.read/write`. Search is case-insensitive; organizations/leads support a `tag` filter. Lead follow-up activities can be updated with `PUT /leads/{id}/activities/{activityId}` using the activity fields above.

Time list responses include a summary across the complete filtered result set: totalHours and billableHours. With finance.read, billableValue and effectiveHourlyRate are included. The effective rate is recorded billable value divided by all recorded hours, not received revenue.
